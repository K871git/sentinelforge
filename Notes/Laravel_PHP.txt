* what is laravel migrations explain with core points: 
laravel migration file are blueprint to create the table:
version-controller database change written in PHP 
describing how to move DB forword and when possible how to undo that change.

up():
-- in up method we define the change that should be made in database when migration runs

-- Migration class provide the up() and down() method
-- at the time of migration the up method get called where all the database changes get instructed
-- at the time of rollback down() method get called

-- Blueprint is the class that provide and let me write and define the table blueprint : Blueprint $table 
-- Blueprint $table is an object that lets you define the structure of a table
-- using of Schema::create(), tells laravel to create table and gives the blueprint through Blueprint object
-- At the time of migration, laravel convert the Blueprint definations into the SQL and executes it against the database 

COMMAND :: php artisan migrate --path database/migrations/<migration name>

down():
-- we write in down method about dropping the tables etc at the time of rollback, 
-- when i rollback that time i need to write the drop or delete to that table
-- if i dont write the drop or dropifexists method then only from migrations table the entry get deleted and table remains in DB

COMMAND ::  php artisan migrate:rollback
            php artisan migrate:reset
            php artisan migrate:rollback --step=1 // most recent how many migration want to rollback
            


Migration
   |
   +-- up()   → Apply the database change
   |
   +-- down() → Undo the database change
